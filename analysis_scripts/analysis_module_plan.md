# 转录组分析模块与图像规划

版本：讨论稿 v2；阶段：规划，不修改或执行分析代码。

## 1. 本轮查阅范围与范围约定

已查阅此前保存的原始代码：class 对应“粘贴的文本 (2).txt”，base 对应“粘贴的文本 (1)(3).txt”。本计划依据函数实际实现整理，不把注释中提及但未实现的功能当作已有能力。尚未在用户服务器验证这些代码是否与当前本地版本完全一致。

- 36 个样本，12 个组合组，首轮 9 个比较；每个处理组与同时间 NC 比较。
- 时间顺序：06、12、24；每个时间内分组顺序：Cat、Leopard、Tiger、NC；重复顺序：1、2、3。
- GO 图只输出 BP；保留 KEGG 图。ORA 与 GSEA 均纳入，包含单组图和多比较图。
- 原代码已实现的图尽可能纳入；有问题的接口先修复，再安排出图，不承诺原封不动直接运行。
- 图像分“主展示组合图、完整单图、补充展示图”。不同展示风格不是不同统计分析。
- 用户说明样本来源为狮子；本项目使用家猫参考 GCF_018350175.1。宿主信息与参考注释物种分别记录，GO/KEGG 基因映射跟随实际参考注释。

## 2. 基座复用与项目组织

| 层级 | 已有实现 | 后续职责 |
|---|---|---|
| 数据容器 | read_counts、object_experiment_design | 保存 counts、Length、注释、样本与比较信息 |
| 注释管理 | PublicDataManager | 解析 NCBI GTF，整合 GeneID、gene2go、KEGG 背景 |
| 单比较计算 | run_calculate_differential_gene、run_calculate_significant_DEG、run_enrichment_analysis | 复用计算，统一参数、结果结构和显著性阈值 |
| 基础绘图 | run_project_visualization、run_pca_style_visualization 及 class 内的 plot_* | 尽量返回图对象，单图与组合图共用结果 |
| 多比较绘图 | tranexp_object 的 compareCluster_* 方法 | 保留四类比较富集图，统一比较顺序、条目选择和图例 |
| 项目运行入口 | 待编写 | 路径、factor、阈值、执行顺序、结果保存 |
| 项目适配与组合 | 仅补必要功能 | 修复输入与注释兼容；收集图对象并组合；避免另建分析框架 |

现有设计对象把 GroupSamples 保存为两列字符矩阵，不能依赖它保存 factor。另存带 Treatment、Time、Replicate 的样本信息表，并在每个绘图数据框中显式恢复 levels。原始文件与输入身份保留，适配后的输入另行保存。

## 4. 模块一：输入、设计与注释

### 4.1 小分析

1. 核对 36 列样本、12 个组合组、9 个比较及每组 3 个重复。
2. 检查样本/基因重复、缺失值、负 count、非整数值及异常 Length。
3. count 列严格与样本表对齐；Length 不进入计数矩阵。
4. 保存原始 counts 和长度；保留现有 TPM、FPKM 计算能力供描述性展示。
5. 解析同版 GTF，建立输入 Geneid、SYMBOL、ENTREZID、描述的对应关系。
6. 检查一对多映射；不能用任意第一条或简单删除 LOC 前缀替代正式映射。
7. 整合 gene2go 与 KEGG；记录来源、版本、下载日期和缓存对应关系。
8. 将全部受检基因、GO 可注释基因、KEGG 可注释基因分别保存。

## 5. 模块二：表达概况与样本关系

### 5.1 小分析

- 统计每个样本的计数总和、检出基因数与零计数比例。计数总和不称为实际测序 reads 总数。
- 首先做有明确规则的表达过滤。run_filter_zero_gene 已注明面向蛋白丰度，不作为本次 RNA-seq 的默认过滤。
- 全样本可视化使用统一生成的标准化表达矩阵；优先评估 logCPM 等用于样本间比较的表示。TPM/FPKM 作为补充，不代替 count 差异模型。
- PCA 的输入转换、center、scale、基因选择在所有风格中保持一致；旧 FactoMineR 与新 prcomp 不能不说明差异就混作同一次 PCA。
- 异常样本仅标记和追踪，不自动删除。

## 6. 模块三：差异表达与基因集合

### 6.1 小分析

- 首轮优先复用已有 edgeR 路线，9 个比较分别保留完整受检表、显著 DEG 表、上调/下调表、过滤与标准化信息。
- 建议讨论默认阈值为 FDR<0.05、|log2FC|≥1；正式实施前统一确定，并使表格、火山图、集合图、ORA 使用相同规则。

- 当前主比较为同时间处理组相对 NC。时间内变化、处理间比较及交互作用留作后续扩展，需确认生物学重复与批次结构。

## 11. 模块八：结果汇总、图像组合与可追溯保存

### 11.1 组合技术与视觉规则

- 先收集图对象，再统一组合和保存，避免“函数既写出又不返回图”的流程阻断。
- ggplot、pheatmap的gtable、GSEA多层图、UpSet/base图分别适配；最终尽量保留文字与线条的矢量属性。
- Pathview以原生图像为准，可作为拼图面板嵌入；嵌入PDF也不宣称全图矢量。花朵图若只能输出栅格，则保留清晰原图并说明来源。
- 三比较面板按时间顺序；九比较面板固定3×3。标签过长或内容过密时拆成时间页，不能只放大画布而保持文字极小。
- 每张组合图有A/B/C面板编号、比较名称和图例。图例只有在含义与尺度完全一致时才共享。
- 样本组配色、表达方向配色、连续表达色标和富集显著性色标各自固定，不把它们混成一套颜色含义。
- 先按合理尺寸范围输出；PDF与PNG使用同主名、相同物理尺寸，PNG默认300dpi。实际出图后逐页检查标签、重叠、图例与空白。

### 11.2 结果结构

结果按项目输入、样本QC、比较结果、注释背景、比较富集、图像六个主要分支保存。每个比较内部保存DEG、GO-BP ORA、KEGG ORA、GO-BP GSEA、KEGG GSEA；不同算法与方向不覆盖。

保存内容：RDS保留统计对象与图对象；TSV/XLSX保留可交换表格；PDF/PNG保留单图与组合图；图像索引记录图号、函数、输入范围、阈值、实际展示条目和文件路径。
